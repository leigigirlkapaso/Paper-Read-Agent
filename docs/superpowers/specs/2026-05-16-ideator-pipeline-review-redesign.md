# 管道重排 + 多轮辩论审查 设计

**日期：** 2026-05-16
**范围：** 管道阶段重排、S3 多轮辩论审查、前端来源显示

---

## 问题

1. S3 审查对着 S2 的一句话火花打分，意义不大——应该是深化后的完整草稿
2. S3 审查是静默打分，R1/R2 互不可见，没有辩论过程
3. S3 管道审查和 AgentTeam 圆桌之间缺递进关系
4. 前端火花卡不显示来源文献
5. 审查记录保存有 bug（spark_id=0）

---

## 设计

### 整体管道重排

```
S0 CrossRecall (6路) → S1 Per-Pair Score (逐对)
→ S2 Spark Generate (C1分组) → S5 Deepen (生成完整研究草稿)
→ S3 Multi-Round Debate Review (7坐席) → S4 Dedup Save
→ S6 Audit
→ [用户发起圆桌: AgentTeam 深度讨论，S3辩论上下文作为起点]
```

关键变化：
- S5 深化移到 S3 之前（先有草稿再审查）
- S3 从简单双模型打分**替换为**多轮辩论审查
- 旧 S3 代码退役，旧 S5 也退役（deepen 逻辑内嵌到辩论中）

### 8 坐席模型分配

| 坐席 | seat_id | 模型 | 角色 |
|------|---------|------|------|
| 生成者 | gen | deepseek-v4-pro | 生成草稿 + 辩论中辩护 |
| 审查者 α | rev1 | deepseek-v4-pro | 新颖性审查 |
| 审查者 β | rev2 | deepseek-v4-pro | 证据支撑 + 溯源审计 |
| 审查者 γ | rev3 | deepseek-v4-pro | 可行性审查 |
| 审查者 δ | rev4 | deepseek-v4-flash | 多角度补充审查 |
| 审查者 ε | rev5 | deepseek-v4-flash | 多角度补充审查 |
| 仲裁者 α | arb1 | deepseek-v4-pro | 辩论终止判断 + 终裁 |
| 仲裁者 β | arb2 | deepseek-v4-pro | 辩论终止判断 + 终裁 |
| 书记员 | rec | deepseek-v4-flash | 全程旁听记录，不参与辩论 |

### S3 多轮辩论流程

```
阶段 1: 深化
  Gen 收到火花 → 生成完整研究草稿（假设+方法+引证+局限）

阶段 2: 背对背初评
  Rev1-5 独立审阅草稿，各自给出:
    - 分数 (novelty/evidence/feasibility 各 0-1)
    - 质疑点列表 (key_concerns)
    - verdict (PASS/REVISE/REJECT)
  审查者之间互不知晓对方意见
  书记员旁听记录

阶段 3: 多轮辩论（Arb1/Arb2 控制）
  每轮:
    1. 各审查者轮流提出质疑（按 seat_id 顺序: rev1→rev2→...→rev5）
    2. Gen 回应质疑，解释推理链，展示来源证据
    3. 如果审查者要求修改，Gen 修订草稿
    4. Arb1/Arb2 判断:
       - 分歧已充分探讨 → 进入终裁
       - 还需更多讨论 → 下一轮
       - 最大轮次 = 5 (硬上限)
  书记员全程旁听，不发言

阶段 4: 重新打分
  5 审查者在已知所有观点后，独立重新打分

阶段 5: 终裁
  Arb1 + Arb2 综合初评 + 辩论记录 + 重评
  → 最终 verdict + final_score
  → 辩论摘要 (debate_summary) 留存，供圆桌使用

阶段 6: 书记员简报
  Rec 基于全程旁听记录，输出结构化简报:
    - 背景: 火花来源、核心问题域
    - 突破口: 辩论中浮现的关键发现
    - 创新点: 与现有研究的差异
    - 实施方案: 建议的下一步研究方向和方法
    - 遗留争议: 辩论中未解决的分歧点
  简报存入 spark.metadata["s3_briefing"]
  圆桌结束时 Rec 再生成一份 briefing 追加
```

### Gen 的辩论角色

Gen 在辩论中的定位是**解释者**而非对抗者：
- 解释火花推理链条
- 引用来源证据回应质疑
- 承认局限和不确定性
- 按审查反馈主动修改草稿
- 不攻击审查者，不狡辩

### 圆桌递进

S3 产出存入 spark：
- `depth_content`：辩论中 Gen 修订后的最终草稿
- `debate_context`：初评+辩论回合+重评+终裁 → JSON，存入 metadata
- `review_status`：审查结果
- `final_score`：终裁分数

用户发起圆桌时，`debate_context` + `s3_briefing` 作为坐席 System Prompt 的一部分注入，坐席可以看到管道审查的辩论历史 + 书记员简报，在此基础上进行更深的讨论。圆桌结束时 Rec 再生成一份最终简报（`roundtable_briefing`），存入 team_memory。

#### API 改动

`GET /api/sparks` 额外返回：
- `source_titles`: `["论文标题...", "笔记#N"]` — 来源文献名
- `source_refs` 中的 id 不变

`GET /api/sparks/{id}` 新增端点，返回单个火花完整详情：
- `s3_briefing`: 书记员简报（从 metadata 解析）
- `debate_context`: 辩论完整记录（从 metadata 解析）
- `depth_content`: 深化草稿
- `review_records`: 审查记录列表
- `roundtable_briefing`: 圆桌简报（从 team_memory 读取）
